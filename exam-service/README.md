# Служба экзамена CCF

Всё, чего не может статическая страница: банк вопросов, учётные записи, сессии, журнал
выдачи и ключ подписи. Разворачивается на Cloudflare Workers с базой D1.

## Почему не на самом сайте

`aenix.io` — Hugo на GitHub Pages. Статическая страница не может хранить секреты: банк,
положенный в JavaScript, становится публичным, а пароль, проверяемый в браузере, не
проверяется. Поэтому служба живёт отдельно.

Поддомен `exam.cert.workshop.aenix.io`, а не отдельный домен — намеренно: для браузера он остаётся
«своим» по отношению к aenix.io, и куки сессии не попадают под ограничения для третьих
сторон. Иначе экзамен на 90 минут срывался бы у части людей, а воспроизвести это на своей
машине было бы нельзя.

## Что нужно завести

| Переменная | Что это |
|---|---|
| `SIGNING_KEY` | закрытый ключ Ed25519 в PKCS#8, base64. Только в секретах, никогда в репозитории |
| `SIGNING_KID` | идентификатор ключа, попадает в каждый сертификат |
| `PLATFORM_VERSION` | версия Cozystack, к которой привязан экзамен |
| `SITE_BASE` | `https://aenix.io` |
| `BANK` | KV с банком вопросов под ключом `ccf` |
| `DB` | база D1 по `schema.sql` |

Ключ создаётся так:

```bash
node -e '
const c=require("node:crypto").webcrypto;
c.subtle.generateKey({name:"Ed25519"},true,["sign","verify"]).then(async kp=>{
  const priv=await c.subtle.exportKey("pkcs8",kp.privateKey);
  const pub=await c.subtle.exportKey("raw",kp.publicKey);
  const fp=await c.subtle.digest("SHA-256",pub);
  console.log("SIGNING_KEY:", Buffer.from(priv).toString("base64"));
  console.log("публичный (в data/cert_keys.json сайта):", Buffer.from(pub).toString("base64url"));
  console.log("отпечаток:", Buffer.from(fp).toString("hex").slice(0,32));
});'
```

Публичный ключ и отпечаток кладутся в `data/cert_keys.json` сайта. **Порядок важен:** сайт
с новым ключом должен уехать в прод раньше, чем служба начнёт им подписывать, иначе первые
сертификаты не проверятся.

Отпечаток публикуется в трёх местах, которыми управляют разные люди: запись DNS, README
репозитория программы и сам значок. Иначе всё доверие сводится к правам на запись в
репозиторий сайта.

## Что здесь решено и почему

**Выдача вопросов без повторов.** Банк 150, форма 60. При свободной выборке с повторами
две попытки показывают 64% банка, и третья даёт заучившему ожидаемые 73% — порог берётся
без единого знания. Форма собирается сначала из вопросов, которых кандидат ещё не видел:
тогда третья попытка даёт 62,5%, ниже любого разумного порога. Проверено расчётом и
прогоном на банке того же состава, что настоящий.

**Закреплённого за аккаунтом среза банка нет.** В черновике он был главной мерой, и это
была ошибка: при срезе в 90 вопросов человек видит две трети своего набора за заход, и
порог берётся со второй попытки вместо третьей. Мера против заучивания ускоряла его.

**Проходной балл в коде, а не на страницах.** 75%, то есть 45 из 60. Единственный
сопоставимый ориентир — KCNA, тоже теория с вариантами ответов, и там 75%; CKA и LFCS с их
66–70% — практические экзамены с частичным зачётом, их порог сюда не переносится. Число не
публикуется: опубликованное становится обещанием, которое нельзя сдвинуть по данным беты.

**Ответ пишется в момент отправки, а не в конце.** Обрыв связи, закрытая вкладка и
перезагрузка страницы не стоят кандидату ничего: `/exam/state` отдаёт позицию и все
данные ответы.

**Открытая сессия не убивается при повторном входе.** Иначе человек, открывший экзамен на
втором устройстве, терял бы попытку.

**Имя берётся из записи аккаунта.** Если бы его вводил кандидат, один общий аккаунт
выписывал бы сертификаты на весь отдел, и вся криптография защищала бы пустоту.

**Журнал выдачи ведётся.** Проверка сертификата базы не требует — но без журнала нет ни
отзыва, ни ответа на запрос об удалении данных, ни восстановления потерянной ссылки, ни
расчёта настоящего порога по данным беты.

## Чего здесь нет

Соглашения кандидата — документ ещё не написан, а руководство для студентов уже на него
ссылается. Без него отзыв сертификата не на чем основать.
